# 小程序登录注册逻辑优化说明

## 优化前的问题

1. **登录状态管理混乱**
   - `app.js` 和页面中的登录状态检查逻辑不一致
   - 本地存储和全局状态不同步
   - 登录状态可能过期但本地仍有缓存

2. **注册登录流程分离**
   - 注册成功后需要手动登录
   - 用户体验不流畅

3. **状态检查不完整**
   - 只检查本地存储，没有验证服务器状态
   - 可能导致过期状态继续使用

## 优化后的逻辑

### 1. 统一的登录状态管理 (`app.js`)

#### 新增方法：
- `checkLoginStatus(callback)`: 统一的登录状态检查
- `clearLoginStatus()`: 清除登录状态
- `setLoginStatus(userInfo, phoneNumber)`: 设置登录状态

#### 检查流程：
1. 先检查本地存储
2. 如果有本地数据，验证服务器状态
3. 服务器验证成功则保持登录状态
4. 服务器验证失败则清除本地存储
5. 网络错误时保持本地状态（离线模式）

### 2. 优化的注册流程 (`pages/taekwondo/register/index.js`)

#### 新增功能：
- `autoLoginAfterRegistration(phoneNumber)`: 报名成功后自动登录

#### 流程：
1. 用户提交报名信息
2. 报名成功后自动调用登录接口
3. 登录成功后设置登录状态
4. 跳转到"我的"页面
5. 如果自动登录失败，提示用户手动登录

### 3. 优化的登录页面 (`pages/taekwondo/my/index.js`)

#### 主要改进：
- 使用 `app.js` 的统一登录状态检查
- 登录成功后使用统一的状态管理
- 退出登录时清除所有状态

## 数据流程

### 注册流程：
```
用户输入手机号 → 提交报名 → 创建registrations和students记录 → 自动登录 → 设置登录状态 → 跳转我的页面
```

### 登录流程：
```
用户输入手机号 → 验证登录 → 设置登录状态 → 加载用户数据 → 显示用户信息
```

### 状态检查流程：
```
启动小程序 → 检查本地存储 → 验证服务器状态 → 设置全局状态 → 更新页面状态
```

## 关键改进点

1. **状态一致性**
   - 所有页面使用统一的登录状态管理
   - 本地存储和全局状态保持同步

2. **用户体验**
   - 注册成功后自动登录，无需手动操作
   - 登录状态持久化，重启小程序后保持登录

3. **错误处理**
   - 网络错误时的降级处理
   - 服务器验证失败时的状态清理

4. **安全性**
   - 定期验证服务器状态
   - 过期状态自动清理

## 使用说明

### 开发者使用：
```javascript
// 检查登录状态
app.checkLoginStatus((isLoggedIn, userInfo) => {
  if (isLoggedIn) {
    // 已登录
  } else {
    // 未登录
  }
});

// 设置登录状态
app.setLoginStatus(userInfo, phoneNumber);

// 清除登录状态
app.clearLoginStatus();
```

### 用户使用：
1. **新用户**：在报名页面输入手机号，提交后自动登录
2. **老用户**：在我的页面输入手机号登录
3. **已登录用户**：重启小程序后自动保持登录状态

## 注意事项

1. 确保云函数 `userLogin` 和 `getUserInfo` 正常工作
2. 网络异常时会有降级处理，但建议在网络恢复后重新验证
3. 登录状态会持久化，用户需要主动退出登录
4. 建议定期清理过期的登录状态
