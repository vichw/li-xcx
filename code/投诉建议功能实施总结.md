## 🎯 核心特性实现

### 1. ✅ 图片上传（最多5张）

**实现位置**：
- 小程序：`pages/feedback/feedback-submit/index.js`
- 云函数：`feedbackFunctions/index.js` → `submitFeedback`

**技术要点**：
- 使用 `wx.chooseImage` 选择图片（最多5张）
- 使用 `wx.cloud.uploadFile` 上传到云存储
- 支持预览和删除
- 管理端支持点击预览大图

### 2. ✅ 投诉类别动态加载

**实现位置**：
- 小程序：`pages/feedback/feedback-submit/index.js` → `loadCategories()`
- 管理端：`views/Feedback.vue` → `loadCategories()`

**数据来源**：
- 从 `configs` 集合读取 `type='complain'` 的数据

### 3. ✅ 提交人信息自动获取

**实现位置**：
- 小程序：`pages/feedback/feedback-submit/index.js` → `loadUserInfo()`
- 云函数：`feedbackFunctions/index.js` → `submitFeedback()`

**技术要点**：
- 从本地存储读取用户信息
- 如果没有，从 `students` 集合查询
- 自动填充姓名和手机号

### 4. ✅ 访问权限控制

**实现位置**：
- 小程序：所有页面都需要登录后才能访问
- 云函数：使用 `cloud.getWXContext().OPENID` 获取用户身份

**技术要点**：
- 小程序端通过 `app.checkLoginStatus()` 验证
- 云函数自动获取用户openid
- 用户只能查看自己的投诉

### 5. ✅ 4种状态流转

**状态定义**：
- `pending` - 待处理（灰色）
- `processing` - 处理中（橙色）
- `resolved` - 已解决（绿色）
- `closed` - 已关闭（灰色）

**实现位置**：
- 管理端：`views/Feedback.vue` → 处理对话框
- 云函数：`feedbackFunctions/index.js` → `handleFeedback()`

### 6. ✅ 红点显示未读回复数

**实现逻辑**：
1. 管理员回复后，`is_read` 设置为 `false`
2. 云函数 `getUnreadCount()` 查询 `admin_reply != '' && is_read = false` 的数量
3. "我的"页面显示红点和数字
4. 用户查看详情后，调用 `markAsRead()` 标记为已读
5. 红点自动更新

**实现位置**：
- 小程序："我的"页面 → `loadFeedbackUnreadCount()`
- 小程序：详情页 → `markAsRead()`
- 云函数：`getUnreadCount()` + `markAsRead()`

## 📝 使用说明

   - 登录小程序
   - 进入"我的"页面
   - 点击"投诉建议"
   - 点击右上角"+"

   - 点击查看详情

3. **投诉状态说明**：
   - **待处理**：刚提交，管理员还未查看
   - **处理中**：管理员正在处理

   - **已关闭**：无需处理或重复投诉

3. **如何处理投诉**：
   - 点击列表中的"处理"按钮
   - 左侧查看投诉详情和图片
   - 右侧填写处理表单
   - 选择状态、输入回复、填写处理人

## ⚠️ 注意事项

### 1. 云存储配额

- 每个环境有免费配额（5GB）
- 图片上传后占用存储空间
- 如果用户量大，建议：
  - 限制图片大小（单张<5MB）
  - 定期清理无用图片
  - 或升级云开发套餐

### 2. 性能优化

- 列表分页加载（默认20条）
- 图片懒加载
- 避免频繁刷新未读数量
- 建议在 `feedback` 集合上添加索引：
  - `user_openid`
  - `status`
  - `create_time`

### 3. 数据安全

- 用户只能查看自己的投诉
- 管理端需要登录才能访问
- 手机号在管理端列表中脱敏显示
- 详情中显示完整手机号（便于联系用户）

### 4. 维护建议

- 定期导出投诉数据备份
- 关注待处理投诉数量
- 及时回复用户反馈
- 可以定期统计分析投诉类别
